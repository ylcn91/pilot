# Pilot Incompleteness Audit — 2026-06-04

> Source: ultracode workflow `pilot-incompleteness-audit` (run `wf_ae5e8f2c-e38`) — 10 dimension finders → adversarial verification → synthesis. 56 agents / 2.29M tokens / 917 tool calls. 40 findings confirmed after refutation pass (P1:1, P2:14, P3:21, P4:4). Build GREEN at audit time.

## 1. Executive summary

The dominant theme is **built-but-never-wired**: across 40 findings the recurring shape is a feature shipped end-to-end (config field + default + DB column + Prometheus export + tests) where the single producing/consuming line was never added. Two subsystems carry the most debt by a wide margin — **autopilot** (config toggles that silently no-op: `default_environment`, `notify_on_failure`, `max_merges_per_hour`, `version_strategy`, `generate_changelog`; plus dead metrics and unwired escalation/email paths) and **executor backend parity** (claude-code gets DECLINED detection, OOM classification, RSS telemetry, and rich diagnostics that the 3-5 sibling backends never received). A second cluster is **adapter parity**: HTTP retry/backoff, rate-limit re-queue, and skip-reason metrics exist only for GitHub, leaving GitLab/Azure/Linear/Jira to turn transient 429s into hard task failures (Azure DevOps actively *drops* rate-limited work until restart). The single most urgent item is **#31 (CS-3): no `safeGo` panic-recovery wrapper** — the only `recover()` in the non-test tree is synchronous, so an unrecovered panic in any of ~60 production goroutines (backend scanners, RSS sampler, webhook/alert dispatchers) crashes the whole daemon and loses every in-flight task; the panic *sink* (`RecordPanic`, liveness fields) was built but the *source* never written. Observability is the most pervasive casualty: `pilot_api_errors_total`, the three `pilot_poller_*` counters, and `api_error_rate` are all permanently zero, and the default-on `api_error_rate_high` alert can structurally never fire — operators get silently green dashboards. Several user-facing surfaces assert work they never did: `pilot onboard` prints `✓ Connected` with fabricated workspace names for invalid tokens, and the Pilot 91 macOS "Create PR" form discards its own title/description inputs. The working tree is mid-flight on a coherent **GH-201/human-recovery-PR + merged-PR-scan decoupling** change that builds clean and is green.
