# What Pilot is

Pilot is a Go monorepo that turns a ticket (GitHub issue, Linear, Jira, Telegram message…) into a merged pull request, autonomously. A ticket is ingested by an adapter, classified for complexity, executed by an AI coding backend (Claude Code / Codex / Qwen / OpenCode / direct API) inside an isolated git worktree, gated by tests & lint & self-review, opened as a PR, then driven through CI → auto-merge → deploy by the autopilot state machine — while a learning loop mines PR reviews and CI failures into reusable patterns.

1 failing test — internal/executor · TestBuildExecEnv_Defaults 
backend_claudecode_args_test.go:180: did not expect env starting with "ANTHROPIC_BASE_URL=",
  got "ANTHROPIC_BASE_URL=https://api.anthropic.com"

buildExecEnv() returns append(os.Environ(), "PILOT_EXECUTOR=1", ...) and only adds ANTHROPIC_BASE_URL=/ANTHROPIC_AUTH_TOKEN= when the backend has them configured. The test asserts those keys are ABSENT from the full env. When the suite runs in a shell that already exports ANTHROPIC_BASE_URL (e.g. inside Claude Code), the value leaks through os.Environ() and the assertion fails. Production code is correct (inheriting the parent env is intentional, see GH-2371 comment); the TEST is environment-dependent / brittle.

▸ Not a production bug — a brittle, environment-leaking test. Fix the test, not buildExecEnv().

Fix: Snapshot+strip ANTHROPIC_* from os.Environ before constructing the backend, or assert only on the appended slice tail.

    # Refactor areas

    Source-confirmed correctness & security findings first (I read the exact lines), then the headline repo-wide refactors from the cross-cutting audit, then every per-subsystem opportunity (filterable).

    Verified this session — fix these

    HIGH Security Stored-XSS / HTML injection in alert email body
    internal/alerts/channels_email.go:99-100
    alert.Title and alert.Message are written into the HTML email via fmt.Sprintf with NO html.EscapeString. Ticket titles come from external sources (GitHub/Linear/Jira/Slack), so an attacker who can name an issue <script>… delivers live HTML to every alert recipient.
    Fix: Wrap both with html.EscapeString (2-line change).
    HIGH Correctness Research subagents silently ignore the --model flag
    internal/executor/parallel.go:262
    modelFlag is the single string "--model haiku" and is injected as ONE argv element: args = append([]string{modelFlag}, args...). The claude CLI never parses it as flag+value, so every research subagent runs on the DEFAULT model instead of cheap Haiku — silent cost/latency regression.
    Fix: Append two args: "--model", model.
    HIGH Security Non-crypto, collision-prone webhook event IDs
    internal/webhooks/event.go:108-114
    randomString() builds IDs from charset[time.Now().UnixNano()%len] with a time.Sleep(1ns) between bytes. The code comment literally says "in production, use crypto/rand". IDs are guessable and two concurrent callers can collide; also 16 sleeps per ID is needlessly slow.
    Fix: crypto/rand.Read into the byte slice (3-line change, no API impact).
    MEDIUM Correctness Budget percentage divide-by-zero → NaN/Inf
    internal/budget/enforcer.go:156,159
    GetStatus computes (TotalCost / config.DailyLimit) * 100 and the monthly equivalent with no zero-guard. When a limit is 0.0 (disabled/misconfigured) the result is NaN/Inf and propagates into alert thresholds, percent displays and the JSON API.
    Fix: Guard limit==0 (return 0 or a 'disabled' sentinel).
